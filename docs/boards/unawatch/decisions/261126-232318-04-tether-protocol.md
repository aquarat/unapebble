# A framed request and reply protocol with a CRC

- Status: Accepted
- Date: 2026-11-26 23:23 UTC
- Decided by: agent

## Context
The serial port may carry noise (a port prober, a half-written command from
a killed client, stale replies of an earlier session) and the commands can
write memory, so a corrupted command must not run.

## Decision
Each frame carries a magic, a command, a sequence number, a length and zlib's
CRC-32; replies echo the command with bit 7 set and the sequence, and start
with a status. The stub looks for the next magic after a frame with a bad
length or CRC and drops a half frame after 500 ms; the host matches replies
by sequence and skips stale ones. Data is at most 4096 bytes a frame. The
protocol code (`stub/proto.c`) knows nothing of the hardware, so that the
tests run it unchanged on a host against `tether.py`.

## Consequences
A damaged command is never run; a frame that only lost its sync is found
again without a timeout. Requests are not retried automatically: a command
that timed out may have run.
