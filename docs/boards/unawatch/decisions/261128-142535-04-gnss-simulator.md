# A built-in route for the GNSS simulator, with shell controls

- Status: Accepted
- Date: 2026-11-28 14:25 UTC
- Decided by: agent

## Context
Recorded after the fact: decided 2026-11-26. The sport apps had to run in
QEMU and the native simulator, which have no receiver, and the other
simulators are fed from the host, which would need host tooling for a route.

## Decision
`CONFIG_GNSS_SIM` (emulator and native boards) replays, at 1 Hz, a built-in
hilly loop of about 3.1 km near Zurich: about 5:20 per km, 37 m of climb, a
15 s stop at a crossing, about 1.5 m of position noise. It searches for
`CONFIG_GNSS_SIM_TIME_TO_FIX` seconds (8) after each start. The route code
(`drivers/gnss/sim_track.c`) is pure, so host tests replay it.
`gnss signal 0|1` takes the signal away and `gnss hold 0|1` stands still,
for testing the step fallback and auto-pause from the console.
`CONFIG_GNSS_SHELL` is on wherever the simulator is.

## Consequences
The apps can be tried and screenshotted headless in QEMU with no host
feed. A lap takes real time, about 5 min 20 s per km. The location is
fixed. A route of the host's choosing would need the host channel.
