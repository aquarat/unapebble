# The developer access in debug and slot builds, not in release

- Status: Accepted
- Date: 2026-11-27 13:48 UTC
- Decided by: agent

## Context
The feature costs about 16 KiB of code and 32 KiB of RAM, and opens the
memory to a cable while on. Release images are what users install; slot
images are only ever flashed and started through the tether stub, which
gives the same access already.

## Decision
`CONFIG_DEV_USB` is on by default in debug builds and in builds for the
stub's slot (`CONFIG_BOARD_UNAWATCH_TETHER_SLOT`, release ones included),
off in release `.ota` builds and in the Lab. In slot builds
`CONFIG_DEV_USB_FORCE` keeps it on whatever the toggle says (shown as
"Always on"), so that the host that flashed the image keeps its console and
tether port; otherwise `CONFIG_DEV_USB_FOLLOW_VBUS` powers the USB only
while the PMIC reports an input (the charger's online state and its
interrupt), and down at the unplug.

## Consequences
It adds about 16 KiB of code to a debug image (1665 KiB of code), and under
1 KiB, the fault hook and the clock changes, to a release one, which still
fit the packer's 3712 KiB with the resources. A release slot build has no
console (CONSOLE is off in release), only the tether port: test with debug
slot builds. A release build that wants it sets `-DCONFIG_DEV_USB=y`.
