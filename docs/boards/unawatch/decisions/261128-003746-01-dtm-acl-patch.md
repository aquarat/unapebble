# The DTM's ACL paths added by a binary patch of ours: tried, it does not start

- Status: Accepted
- Date: 2026-11-28 00:37 UTC
- Decided by: agent

## Context
Under 261128-001034-01-back-up-and-patch-the-dtm the DTM was backed up and
analysed (hardware.md, 2.5.1): built without `LL_ONLY`, it drops the
host's ACL packets in its HCI parser and its callback for received ACL data
does nothing; the stack functions both paths need are in the image, as is
blank flash after the code.

## Decision
- **The patch.** Our own code, `tools/una/bluenrg2/acl_patch.c` (268
  bytes, built for the Cortex-M0 at 0x10068000, in blank flash): host to
  link layer, a packet buffer from the stack's allocator, filled, flagged
  for a Number Of Completed Packets, queued with its transmit function,
  as the stack's L2CAP does; link layer to host, an H4 ACL packet onto the
  SPI event queue. Two 4-byte BL instructions point the parser's dispatch
  (0x1004e466) and the callback (0x10045e9e) at it. Zero-length ACL
  packets are dropped rather than tracked.
- **The tool.** `tools/una/bluenrg2/patch.py` works only on the known
  image (SHA-256), and only if the chip holds the user's backup: it writes
  the changed 2 KiB pages through the updater (tether experiment
  bluenrg2, mode 11: never the DTM's first page nor the stack's data page),
  reads each back and checks the updater's CRC before restarting the chip,
  and restores the original pages the same way. No ST code is in the
  repository.
- **The outcome.** Written exactly, the patched DTM does not start, nor
  does one with either redirection alone or with one padding byte changed:
  its code is checked before it runs, by something that could not be read
  (inferred: the updater or the ROM). The original was restored and
  verified; `write` now needs `--force`. Writing stops here.

## Consequences
The chip stays on its original DTM. Going further needs the check found:
the updater's code (0x10040000, not readable through itself) read by other
means, such as SWD on the module or ST's ROM UART bootloader on IO7, whose
UART pins are not known to reach the STM32. Otherwise, option (b), ST's ACI
with the stack on the chip (261127-152213-01).
