# Drive the MAX17262 as a device of a new fuel gauge class

- Status: Accepted
- Date: 2026-11-26 17:35 UTC
- Decided by: agent

## Context
PebbleOS's battery service takes the state of charge from a voltage curve,
from Nordic's fuel gauge library or from the open fuel gauge library, all fed
by the measurements of a charger. The UNA Watch has a fuel gauge chip that
estimates the state of charge itself, and a charger, the PCA9420's, that
measures nothing. No class covered a gauge chip; `pbl_fuel_gauge` is the
software library.

## Decision
A small `gauge` driver class (`drivers/gauge`, `pbl/drivers/gauge.h`, role
`GAUGE`) with one operation, a reading: state of charge, voltage, averaged
voltage, current and temperature. The MAX17262 is its first driver. The
PCA9420 is a charger class driver (`drivers/charger/pca9420.c`) for external
power, charge status and charge enable; its measurements return `-ENOTSUP`.
A battery service backend, `BATTERY_SOC_GAUGE` (`pebble/services/battery/
gauge`), the default when the board has a gauge, joins them. Time-to-empty is
not read: nothing in the service needs it.

## Consequences
The charger, battery and battery monitor services work unchanged on top.
Another board with a gauge chip adds a driver to the class. The charger shell
prints no measurements on this board; the `gauge` shell command does.
