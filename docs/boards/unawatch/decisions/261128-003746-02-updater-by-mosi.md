# Enter the BlueNRG-2's updater by holding MOSI high, for recovery

- Status: Accepted
- Date: 2026-11-28 00:37 UTC
- Decided by: agent

## Context
Once a patched DTM did not start, the updater could no longer be entered by
command (`aci_hal_updater_start` needs a running DTM). hardware.md had the
updater's boot pin, IO3, as the SPI MISO line; holding MISO high, pulled
up or driven, did nothing. ST's updater source reads IO3 and calls it the
"SPI MOSI PIN".

## Decision
The tether experiment's updater entry tries a normal start and
`aci_hal_updater_start` first, then, if the DTM does not start, a reset
with MOSI (PB5) driven high through the release and until IRQ rises, CS
high, SCK low: the updater starts with reason 4.

## Consequences
5 of 5 entries this way worked, each with a DTM that did not start, so a
bad DTM image can always be restored through the tether, the backup at
hand. The table of hardware.md's restarts reads in that light: the boot pin
is MOSI.
